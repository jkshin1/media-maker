# Monitoring Data 자연어 검색·시각화 AI Agent
## 이태관 TL 과제 영상 제작 MD

> 목적: 확정된 가로형 5컷 스토리보드를 바탕으로 실제 모션이 있는 16:9 영상 제작  
> 담당: 이태관 TL  
> 핵심 콘셉트: 여러 시스템에 흩어진 공정 데이터를 자연어로 조회하고, Wafer Map·그래프 등으로 시각화해 분석에 활용

---

## 1. 제작 목표

여러 시스템에 흩어진 공정 데이터를 하나씩 확인하던 기존 업무에서 출발한다. 사용자가 자연어로 필요한 데이터를 질문하면 AI Agent가 관련 공정 데이터를 조회·연결하고, 결과를 Wafer Map과 그래프 등으로 시각화해 한눈에 파악할 수 있도록 돕는 흐름을 전달한다.

영상은 다음 순서로 이어진다.

**기존 업무 → 자연어 질문 → 관련 데이터 조회·연결 → 시각화 결과 확인 → 더 빠른 분석과 의사결정 지원**

나레이션은 각 컷이 서로 이어지는 업무 설명형 문장으로 작성한다. 각 컷의 상단에는 장면 제목을 표시하고, 하단에는 내레이션을 별도로 표시한다.

## 2. 공통 제작 규칙

- 화면 비율: 16:9 가로형
- 시각 스타일: 검정·차콜 바탕, 골드·앰버 포인트. 기존 R&D 공정 AI Fast Track 영상 시리즈와 시각적 일관성을 유지한다.
- 기본 색상:
  - Black: `#080808`
  - Charcoal: `#1A1A1F`
  - Gold: `#D4AF7C`
  - Light Gold: `#F5D6A6`
  - Amber: `#FFB347`
  - Cream: `#F2EEE7`
- 고급스럽고 절제된 조명을 사용한다. 과도한 파란색 네온이나 장식적인 HUD 효과는 피한다.
- 16:9 화면 안에서 인물·UI·자막이 잘리지 않도록 안전 여백을 둔다.
- 프로젝트명, 컷 제목, 나레이션 문구는 아래 원고를 기준으로 정확하게 표기한다.
- 스토리보드 한 장을 통째로 정지 화면으로 사용하지 않는다. 이미지 다섯 조각을 잘라 그대로 이어 붙이는 방식도 금지한다.
- 다섯 컷을 각각 독립된 영상 장면으로 제작한다. 실제 카메라 이동, 피사체 움직임, UI 애니메이션, 장면 전환을 구현한다.
- 정지 이미지에 자막과 나레이션만 얹는 슬라이드쇼 방식은 금지한다.
- 실제 기능으로 확인되지 않은 기능·성과·데이터를 사실처럼 추가하지 않는다.
- 영상은 간결하고 템포 있게 구성한다. 긴 정지 구간과 과도하게 느린 페이드아웃을 피한다.
- 최종 결과물은 MP4, 실행 가능한 소스 코드, 실행 방법 안내를 포함한다.

## 4. 컷별 제작 지시

각 컷의 상단에는 아래 **장면 제목**을 표시하고, 그 아래 또는 화면 하단에는 해당 **나레이션**을 자막으로 표시한다. 장면 제목과 나레이션은 서로 다른 텍스트 요소로 구현한다.

### CUT 1 — 데이터를 찾는 어려움
**권장 시간:** 0–6초

**장면 제목**
`데이터를 찾는 어려움`

**나레이션**
> 여러 시스템에 흩어진 공정 데이터를 하나씩 확인하던 업무를,

**화면 구성**
- 연구원이 여러 모니터와 자료를 오가며 공정 데이터를 확인한다.
- SmartMES, GMS, Data Lake / HCP, Excel 파일 등 서로 다른 데이터 출처를 시각적으로 보여준다.
- 자료가 각각 다른 화면과 창에 있어 한 번에 확인하기 어려운 상황을 표현한다.
- 화면을 단순한 UI 카드 나열로 만들지 말고, 연구원과 여러 시스템 화면을 함께 보여주는 공간감 있는 구도로 구성한다.

**카메라·모션**
- 여러 모니터를 따라 가로로 이동하는 트래킹 샷.
- 서로 다른 시스템 창이 각각 열리고, 연구원이 화면을 확인하는 움직임.
- 여러 데이터 출처가 각기 다른 위치에 있다는 점을 강조한다.
- 마지막에는 여러 창 중 하나가 강조되며 CUT 2의 질문 화면으로 연결된다.

---

### CUT 2 — 자연어로 질문
**권장 시간:** 6–12초

**장면 제목**
`자연어로 질문`

**나레이션**
> 자연어로 필요한 데이터를 질문하고,

**화면 구성**
- 연구원 앞의 Monitoring Data AI Agent 인터페이스를 클로즈업한다.
- 자연어 질문이 입력되는 장면을 보여준다.
- 시안 속 질문 문구는 연출용 예시다. 실제 사용 가능한 질문으로 확인되지 않은 문구를 기능 보장처럼 표현하지 않는다.
- 질문이 기존의 복잡한 시스템 화면 대신 간결한 대화형 인터페이스로 이어지는 모습을 표현한다.

**카메라·모션**
- 연구원의 어깨 너머에서 화면으로 천천히 푸시인.
- 입력창에 질문이 타이핑되듯 나타난다.
- 전송 시 입력창이 짧게 강조되고, 화면이 CUT 3의 데이터 조회 장면으로 전환된다.
- 타이핑 속도는 자연스럽고 빠르게 유지한다.

---

### CUT 3 — 관련 데이터 자동 조회
**권장 시간:** 12–18초

**장면 제목**
`관련 데이터 자동 조회`

**나레이션**
> AI Agent가 관련 공정 데이터를 조회해 연결하고,

**화면 구성**
- SmartMES, GMS, Data Lake / HCP, 장비 데이터 등 여러 출처가 AI Agent와 연결되는 시각화를 보여준다.
- 관련 데이터가 조회되어 하나의 화면에서 확인할 수 있도록 모이는 과정을 표현한다.
- 데이터 연결은 이번 장면의 시각적 핵심이다.
- 실제 데이터 연계 범위가 확인되지 않은 시스템이나 필드를 추가하지 않는다. 최종 제작 시 과제 자료에서 확인되는 시스템 범위만 사용한다.

**카메라·모션**
- 중앙의 AI Agent를 중심으로 데이터 출처들이 순차적으로 활성화된다.
- 골드 라인이 각 출처에서 AI Agent를 거쳐 결과 영역으로 이어진다.
- 연결선이 한꺼번에 폭발하듯 나타나지 않도록 순차적으로 연결한다.
- 카메라가 중앙에서 결과 패널 쪽으로 이동하며 CUT 4로 전환한다.

---

### CUT 4 — 시각화된 분석 결과 제공
**권장 시간:** 18–27초

**장면 제목**
`시각화된 분석 결과 제공`

**나레이션**
> Wafer Map과 그래프로 시각화해 한눈에 파악하고,

**화면 구성**
- Wafer Map과 그래프를 주요 시각 요소로 보여준다.
- 데이터 요약과 그래프가 분석 결과 화면 안에 정돈되어 나타난다.
- 시각화는 사용자가 조회한 데이터를 이해하기 쉽게 표현하는 데 초점을 둔다.
- 구체적인 이상 원인, 원인 순위, 장비별 수치, Lot 결과 등은 근거 자료에 확인되지 않으면 임의로 추가하지 않는다.
- 시안의 그래프는 시각적 예시이며, 실제 분석 결과인 것처럼 오해할 수 있는 수치나 레이블은 검증 후 사용한다.

**카메라·모션**
- 분석 결과 대시보드로 부드럽게 푸시인.
- Wafer Map이 먼저 나타나고, 그래프가 이어서 활성화된다.
- 그래프는 선이 그려지거나 막대가 차례로 올라오는 방식으로 움직인다.
- 사용자의 시선이 Wafer Map에서 그래프로 이동하도록 포커스를 순차적으로 전환한다.

---

### CUT 5 — 더 빠르고 정확한 분석
**권장 시간:** 27–34초

**장면 제목**
`더 빠르고 정확한 분석`

**나레이션**
> 데이터 분석 시간을 단축해 더 빠른 의사결정을 지원합니다.

**화면 구성**
- 연구원이 Wafer Map과 그래프를 확인하며 공정 데이터를 파악하는 모습을 보여준다.
- 복잡한 데이터 조회 과정에서 정돈된 분석 결과 화면으로 시각적 대비를 만든다.
- 마지막은 분석 화면과 웨이퍼 또는 공정 장비를 함께 보여주며 마무리한다.
- 성과 자료에서 확인된 경우에만 `데이터 분석 시간 40% 이상 단축` 문구를 사용한다. 해당 수치가 본 과제의 검증된 성과인지 확인되지 않으면 화면에서 제외한다.

**카메라·모션**
- 연구원과 분석 화면을 함께 담은 미디엄 샷에서 시작한다.
- 분석 화면에서 웨이퍼로 시선이 이동하도록 카메라를 천천히 이동한다.
- 골드 포인트 조명이 웨이퍼 표면을 지나가며 마무리한다.
- 마지막 화면은 짧게 유지하고 다음 영상으로 연결할 수 있도록 끝낸다.

## 5. 나레이션 전체 원고

1. 여러 시스템에 흩어진 공정 데이터를 하나씩 확인하던 업무를,
2. 자연어로 필요한 데이터를 질문하고,
3. AI Agent가 관련 공정 데이터를 조회해 연결하고,
4. Wafer Map과 그래프로 시각화해 한눈에 파악하고,
5. 데이터 분석 시간을 단축해 더 빠른 의사결정을 지원합니다.

### 나레이션 연출 지침
- 다섯 문장은 한 편의 이야기처럼 자연스럽게 이어지도록 녹음한다.
- CUT 1의 문장은 다음 컷으로 이어지는 도입부이므로, 문장을 완전히 종결하는 어조로 과하게 끊지 않는다.
- 컷마다 음성을 새로 시작하는 듯한 단절을 피하고, 한 흐름으로 이어 읽는다.
- 톤은 명확하고 전문적인 기업 성과공유회 스타일로 유지한다.
- 문장을 임의로 늘리거나 반복하지 않는다.

## 6. 사운드 및 전환

- 배경음악: 절제된 시네마틱 전자음과 일정한 리듬. 과도하게 웅장하거나 감성적으로 만들지 않는다.
- CUT 1: 여러 화면을 확인하는 공간감 있는 저음과 미세한 UI 사운드.
- CUT 2: 질문 입력과 전송 시 절제된 인터페이스 사운드.
- CUT 3: 데이터 출처가 연결될 때 짧고 부드러운 전자음.
- CUT 4: Wafer Map과 그래프가 나타날 때 은은한 상승음.
- CUT 5: 음악을 짧게 정리하며 다음 과제로 연결한다.
- 모든 컷에 동일한 페이드 효과만 반복하지 않는다. 트래킹, 푸시인, 연결선 애니메이션, 포커스 이동을 장면별로 다르게 사용한다.

## 7. 정확성 및 금지사항

- 검증되지 않은 기능이나 데이터 출처를 임의로 추가하지 않는다.
- 자연어 질의, 관련 데이터 조회·연결, Wafer Map·그래프 시각화라는 핵심 흐름을 유지한다.
- 자동 이상 원인 판정, 원인 순위 제공, 자동 조치 등 확인되지 않은 기능을 추가하지 않는다.
- 성과 수치 `40% 이상 단축`은 공식 과제 자료로 확인되는 경우에만 사용한다.
- 임의의 Lot ID, 수율, 장비 수치, 이상 원인, 분석 결과를 실제 성과처럼 노출하지 않는다.
- 장면 제목과 나레이션은 모두 유지한다. 제목을 빼거나 나레이션만 화면에 표시하지 않는다.
- 컷별 장면 제목은 각 화면 상단에, 나레이션 자막은 별도의 하단 영역에 배치한다.
- 권혜선 TL 과제와 전체 디자인 규칙은 통일하되, 이번 과제는 시스템 연결과 데이터 시각화가 중심이 되도록 연출을 차별화한다.
